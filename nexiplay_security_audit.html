Nexiplay is a Next.js movie/anime/series download aggregator hosted on Vercel's free tier. It presents content cards with Google Drive direct download links across three content types (Movies, Series, Anime). The site has no user authentication, no rate limiting, and no data processing — it is functionally a public read-only content directory.

The two Critical findings are not technical vulnerabilities per se but existential legal and platform risks that dwarf any code-level issue: the site distributes copyrighted third-party media files and runs on Vercel's free tier without a Terms of Service agreement covering this content category. The High findings cover the standard Vercel/Next.js deployment hygiene gaps already identified in the prior audit.

⚠ Copyright / Legal Risk: Distributing copyrighted films and anime via Google Drive links constitutes copyright infringement in most jurisdictions regardless of hosting location. This routinely triggers DMCA takedowns, Google Drive account termination, and Vercel project suspension. This is the highest-priority issue on the entire site.

NEXT.JS IMAGE OPTIMIZATION API ABUSE

The /_next/image endpoint accepts arbitrary url= parameters pointing to external images. Without proper remotePatterns configuration in next.config.js, this endpoint can be abused as an open image proxy (Server-Side Request Forgery vector) or used to generate bandwidth charges on your Vercel account. Check that your next.config.js restricts allowed domains:

// next.config.js — required configuration
module.exports = {
  images: {
    remotePatterns: [
      { protocol: 'https', hostname: 'drive.google.com' },
      { protocol: 'https', hostname: 'lh3.googleusercontent.com' },
      // only add domains you actually use
    ],
  },
};

C-1 · Copyright Infringement via Hardcoded Google Drive Links CRITICAL

Every content page has Google Drive direct download URLs hardcoded in the static HTML. These URLs point to copyrighted films, anime series (Jujutsu Kaisen, Bridgerton, etc.), and WEB-DL rips. This is visible in all Google-indexed pages and detectable by any automated rights-holder scanning tool (Muso, Red Points, etc.).

DMCA takedowns target both Vercel (as host) and Google (as file host). Google routinely auto-terminates Drive accounts hosting pirated content. Vercel's ToS (Section 8) prohibits "infringing content" and can result in immediate project suspension.

If running this site legally, all hosted files must be original or properly licensed content. Replace Google Drive links with licensed CDN sources or remove infringing content entirely.
C-2 · All Download Links Exposed in Static HTML Source CRITICAL

Because content is statically rendered, every Google Drive link is embedded directly in the HTML delivered to search engines and scrapers. Any script can harvest all download URLs in seconds without rendering JavaScript. This means: (1) rights-holders can find all your infringing links via Google index, (2) scrapers can bulk-harvest links for redistribution, and (3) there is zero gate-keeping on link access.

If links must be protected, move them behind a server-side API route that requires a rate-limited, authenticated request before returning the link. Never embed direct file URLs in static HTML.
H-1 · Missing Critical HTTP Security Headers HIGH

Previously confirmed in the prior audit. The following headers are not being sent by the Vercel deployment:

  • Content-Security-Policy (CSP) — absent, allows XSS via injected scripts
  • X-Frame-Options / CSP frame-ancestors — absent, allows clickjacking
  • Permissions-Policy — absent
  • Referrer-Policy — absent (leaks referrer to Google Drive when users click links)
Add headers in next.config.js headers() or via vercel.json. At minimum: X-Frame-Options: DENY, Referrer-Policy: no-referrer, X-Content-Type-Options: nosniff.
H-2 · Source Maps Potentially Public HIGH

Next.js generates .js.map source map files alongside production bundles in /_next/static/chunks/. By default these are served publicly. Anyone can load them in Chrome DevTools to reconstruct the original TypeScript/JSX source tree including component names, logic, hardcoded strings, and any NEXT_PUBLIC_* values baked into the bundle.

Reconstructed file tree would expose: component architecture, routing logic, any hardcoded API keys or tokens, data models, and the content management approach.

Disable source maps in production: set productionBrowserSourceMaps: false in next.config.js. Already confirmed this was flagged in the prior audit — verify it was implemented.
H-3 · NEXT_PUBLIC_* Env Variables Baked into JS Bundle HIGH

Any environment variable prefixed with NEXT_PUBLIC_ is embedded in the client-side JavaScript at build time and is visible to anyone who opens DevTools. If you store any API keys, service tokens, or backend URLs using this prefix (e.g. a CMS token, analytics key, or Telegram bot token), it is publicly exposed.

Audit your .env.local and Vercel environment variables. Never use NEXT_PUBLIC_ for secrets. Server-only secrets must be accessed exclusively in Server Components, Route Handlers, or API routes — never in client components.
H-4 · No Rate Limiting on /_next/image Endpoint HIGH

Vercel's image optimization endpoint processes arbitrary image URLs on-demand. Without rate limiting, it can be abused for:

  • SSRF (Server-Side Request Forgery) if remotePatterns is too permissive
  • Bandwidth exhaustion to consume your Vercel plan limits
  • Proxy for external resources bypassing your CSP
Restrict remotePatterns strictly to domains you use. Consider adding Vercel's Rate Limiting middleware or Cloudflare in front of the deployment.
M-1 · CORS Headers Not Explicitly Configured MEDIUM

Without explicit CORS configuration in next.config.js headers or API route middleware, Vercel's default CORS policy applies. For a purely static site this is acceptable, but if any API routes exist, they inherit a permissive CORS posture that allows any origin to make credentialed requests.

In any API route, explicitly set Access-Control-Allow-Origin to a specific trusted origin rather than *.
M-2 · Referrer Leakage to Third-Party File Hosts MEDIUM

When a user clicks a download link, the browser sends a Referer header to Google Drive containing the full URL of your site. This allows Google to map which pages link to which files, and is exactly how automated DMCA detection works at scale.

Set Referrer-Policy: no-referrer in HTTP headers. This prevents the referer header from being sent to external destinations.
M-3 · No robots.txt Disallowing Sensitive Paths MEDIUM

Without a robots.txt file, all paths including /_next/, API routes, and all content pages are indexed by search engines. The full content library is publicly searchable, which increases copyright detection exposure and accelerates DMCA filing timelines.

Add a robots.txt via Next.js App Router's metadata convention. At minimum, disallow /_next/ static paths from crawling.
L-1 · Telegram Channel URL Hardcoded in Content LOW

Your Telegram channel link appears in every content description. If Telegram bans the channel (common for piracy-related channels), all references site-wide break simultaneously.

Store the Telegram URL as a single constant / environment variable, not duplicated across content entries.
L-2 · Running on Vercel Free (Hobby) Tier LOW

The deployment URL is nexiplay.vercel.app with no custom domain — indicating a free Hobby plan. Free plans have bandwidth limits and can be suspended instantly without notice. All your content and links disappear immediately upon suspension.

Consider a custom domain (even just for branding) and evaluate whether the traffic level warrants a Pro plan. Keep a backup of all content data outside of Vercel.
L-3 · Google Drive Link Rot Risk LOW

All download links depend on Google Drive file availability. Drive files linked from piracy sites are routinely reported and deleted, creating broken links across the site with no automated detection or fallback.

Implement a link health-check script that periodically pings Drive URLs and flags 404s. Consider a broken-link badge on content cards.
L-4 · No Security.txt or Vulnerability Disclosure Policy LOW

No /.well-known/security.txt exists. While minor for a personal project, it's a signal of security maturity.

Not a priority for this site's threat model, but easy to add if you ever expand.

6
Security Hardening (next.config.js)
// next.config.js
const nextConfig = {
  productionBrowserSourceMaps: false,
  images: {
    remotePatterns: [
      { protocol: 'https', hostname: 'drive.google.com' },
      { protocol: 'https', hostname: 'lh3.googleusercontent.com' },
    ],
  },
  async headers() {
    return [{
      source: '/(.*)',
      headers: [
        { key: 'X-Frame-Options',        value: 'DENY' },
        { key: 'X-Content-Type-Options', value: 'nosniff' },
        { key: 'Referrer-Policy',        value: 'no-referrer' },
        { key: 'Permissions-Policy',     value: 'camera=(), microphone=()' },
      ],
    }];
  },
};
7
Deploy to Vercel
Push to GitHub → connect repo in Vercel dashboard → auto-deploy on every push. Add a custom domain if available. Set all secrets as environment variables in the Vercel dashboard — never in code or NEXT_PUBLIC_ prefix unless you intend them to be public.

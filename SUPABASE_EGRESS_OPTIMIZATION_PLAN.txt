============================================================
NEXIPLAY - SUPABASE EGRESS REDUCTION PLAN
============================================================
Project: NexiPlay (Public Site) + NexiPlay Admin Panel
Goal: Reduce Supabase egress by 70%+ to stay within Free Tier
Tech Stack: Next.js 14 (App Router), TypeScript, Supabase, Vercel Free Tier
============================================================

CURRENT PROBLEM:
================
Every single page load triggers 5-10 Supabase API calls from client-side components.
Many queries use select('*') fetching entire rows when only a few columns are needed.
Multiple components fetch the same data independently (duplicates).
Detail page revalidates every 60 seconds (too aggressive).

============================================================
FULL AUDIT RESULTS
============================================================

PROJECT STRUCTURE:
- Public site: d:\Nexiplay (Next.js App Router)
- Admin panel: d:\nexiplay-admin (Next.js App Router)
- Layout file: src/app/(site)/layout.tsx renders Header, AnimatedTelegramCTA, ClientChatbot, Footer on EVERY page

------------------------------------------------------------
ISSUE #1: LAYOUT-LEVEL COMPONENTS (Fires on EVERY page load)
------------------------------------------------------------

These 4 components are rendered via layout.tsx so they fire on every single page navigation:

1. AnimatedTelegramCTA (src/components/AnimatedTelegramCTA.tsx)
   - Fetches: supabase.from('telegram_settings').select('*').eq('id', 1).single()
   - Fires: Every page load
   
2. Chatbot (src/components/Chatbot.tsx) - loaded via ClientChatbot.tsx with dynamic import ssr:false
   - Fetches: supabase.from('chatbot_settings').select('*').single()
   - Fetches: supabase.from('faqs').select('*').eq('is_active', true)
   - Also has: setInterval for header text rotation (not a DB call, just UI animation - OK)
   - Fires: Every page load (even though 99% of users never open the chatbot)
   
3. NoticeSystem (src/components/NoticeSystem.tsx) - rendered inside Header
   - Fetches: supabase.from('notices').select('*').eq('is_active', true)
   - Fires: Every page load
   
4. useAdSettings hook (src/hooks/useAdSettings.ts) - used by AdProvider in root layout
   - Fetches: supabase.from('app_settings').select('*').eq('id', 1).single()
   - Has in-memory cache (cachedSettings) but still fetches once per page refresh
   - Fires: Every page load (first load)

TOTAL: 5 Supabase calls on EVERY page load just from layout components

------------------------------------------------------------
ISSUE #2: DUPLICATE FETCHES
------------------------------------------------------------

A. app_settings table fetched TWICE:
   - useAdSettings.ts fetches app_settings for ad configuration
   - HeroSlider.tsx ALSO fetches app_settings independently for popunder_url
   FIX: HeroSlider should use the shared useAdSettings hook or get settings from AdProvider context

B. telegram_settings table fetched up to 3 TIMES per detail page:
   - AnimatedTelegramCTA.tsx (in layout, every page)
   - TelegramButton.tsx (rendered on detail page, TWICE - desktop + mobile instances)
   FIX: Create shared settingsCache module, fetch once per session

C. generateMetadata duplicates page query on detail page:
   - File: src/app/(site)/[type]/[slug]/page.tsx
   - generateMetadata() fetches: supabase.from('movies').select('*').eq('slug', rawSlug)...
   - MovieDetailPage() fetches: supabase.from('movies').select('*, downloads(*), download_links(*)...')
   - The second query includes everything the first needs
   FIX: generateMetadata should select only metadata fields OR share data with the page function

------------------------------------------------------------
ISSUE #3: AGGRESSIVE REVALIDATION
------------------------------------------------------------

Current revalidation times:
- Detail page [type]/[slug]/page.tsx: revalidate = 60 (every minute!)
- Home page (site)/page.tsx: revalidate = 300 (every 5 min)
- Movies listing: revalidate = 300
- Series listing: revalidate = 300
- Anime listing: revalidate = 300

Problem: Detail page revalidating every 60s means Supabase gets hit constantly by Vercel's ISR.
Content details (movie info, download links) rarely change.

FIX:
- Detail page: revalidate = 3600 (1 hour)
- Home page: revalidate = 900 (15 minutes)
- Listing pages: revalidate = 900 (15 minutes)

------------------------------------------------------------
ISSUE #4: select('*') EVERYWHERE
------------------------------------------------------------

These components fetch ALL columns when they only need a few:

1. SearchBar.tsx (src/components/SearchBar.tsx)
   - CURRENT: supabase.from('movies').select('*').ilike('title', `%${query}%`).limit(8)
   - NEEDS: id, title, slug, type, poster_url, release_year
   - FIX: .select('id, title, slug, type, poster_url, release_year')

2. RelatedPosts.tsx (src/components/RelatedPosts.tsx)
   - CURRENT: supabase.from('movies').select('*').eq('type', type).neq('id', currentMovieId).limit(10)
   - NEEDS: id, title, slug, type, poster_url, release_year, created_at
   - FIX: .select('id, title, slug, type, poster_url, release_year, created_at')

3. CommentSection.tsx (src/components/CommentSection.tsx)
   - CURRENT: supabase.from('comments').select('*').eq('movie_id', movieId)
   - NEEDS: id, name, message, created_at
   - FIX: .select('id, name, message, created_at')

4. NoticeSystem.tsx (src/components/NoticeSystem.tsx)
   - CURRENT: supabase.from('notices').select('*').eq('is_active', true)
   - NEEDS: id, type, content, pages, bg_color, text_color
   - FIX: .select('id, type, content, pages, bg_color, text_color')

5. Chatbot.tsx (src/components/Chatbot.tsx)
   - chatbot_settings: select('*') - needs: is_enabled, bot_name, welcome_message
   - faqs: select('*') - needs: question, answer, keywords, is_active

6. Running Tasks (admin) (src/app/running/page.tsx)
   - CURRENT: supabase.from('movies').select('*').eq('is_running', true)
   - NEEDS ONLY: id, title, type, poster_url, last_episode, next_episode, next_episode_date, admin_note, notify_admin, is_running, running_status

7. Admin useSupabaseQuery hook (src/hooks/useSupabaseQuery.ts)
   - Always uses select('*') as default
   - Should allow passing select fields

------------------------------------------------------------
ISSUE #5: NO CLIENT-SIDE CACHING
------------------------------------------------------------

No sessionStorage or localStorage caching for:
- Notices (same data every page)
- Telegram settings (same data every page)
- Ad settings (same data every page)

FIX: Cache these in sessionStorage with a TTL (e.g., 5 minutes):
- First load: fetch from Supabase, store in sessionStorage
- Subsequent navigations: read from sessionStorage
- After TTL expires: re-fetch
